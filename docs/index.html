OneLoop

Most coding agents are built around a vendor.
OneLoop is built around your subscriptions.

One agent for your Claude, ChatGPT, Antigravity, OpenRouter, and OpenCode subscriptions — plus local when you want private.
One loop, six tools, no framework.

core idea

One Agent Loop

Think → call tools → feed results back → repeat.
No plugins, no hooks, no middleware.

models

Any Model

One agent for your Claude, ChatGPT, Antigravity, OpenRouter, and OpenCode subscriptions — plus a local model when you want private.
Reach a hosted one only when you ask for it.

A provider is an endpoint — one URL, one credential, one connection pool. Credentials may be absent, an API key, or a renewable subscription grant. Its models get short aliases: qwen, luna, nvidia. /model switches which one answers for the session.

The same code serves llama-server, OpenRouter, and OpenCode Go over Chat Completions, plus ChatGPT's Codex backend and OpenCode Go Responses models over the Responses API.

Edit ~/.oneloop/config.json, then use /reload to refresh providers and models without restarting or clearing the conversation. Your current model stays selected while its alias exists; changing default alone does not switch it. If reloading fails, the working configuration stays untouched.

multi-model

One session, many models

Switch mid-conversation. Plan with the expensive model,
implement with the cheap one, ask a third for a second opinion.

(nvidia)> /model luna; plan how to split the parser
(luna)> /model nvidia; implement step 1 of that plan
(nvidia)> /ca is the plan still consistent with the code?

A command can carry a prompt across the ; boundary, so switching and asking is one line. Every answer is recorded in the same append-only session.

optional CLI subscriptions

Claude Code and Antigravity

When the corresponding CLI is installed, /help lists its slash commands. Claude Code uses /cc, /ca, and /cn; Antigravity uses /ag, /aga, and /agn.

These commands use your existing CLI subscription and keep your selected OneLoop model unchanged. The answer comes back as a reference message in this session, so the current model can reason about it. OpenAI subscriptions are supported separately through the Codex provider and ./ol login openai.

no request

Your own commands

Lead a line with ! to run bash yourself. The output is printed, then recorded in the session as reference material — no request is made, so nothing is spent until you ask for something.

(nvidia)> !cargo test 2>&1 | tail -20
(nvidia)> those two failures are mine — fix them

Everything after ! goes to the shell verbatim, so a ; there is a separator rather than a prompt boundary. Commands that succeed are appended to your own $HISTFILE, which is what ! completion reads back.

skills

Skills

Markdown playbooks the model loads on demand.
Not in the system prompt — pulled in only when needed.

~/.oneloop/skills/code-review.md
.oneloop/skills/changelog.md
.oneloop/skills/migration.md

The model sees names + descriptions at startup.
It calls skill("name") when the task matches — no user action needed.

reliability

Append-only sessions

Every message, tool call, and result is appended to a JSONL file.
No mutation, no corruption.

.oneloop/sessions/2025-07-11.jsonl
.oneloop/sessions/2025-07-11-001.jsonl
reliability

No compaction

Nothing is summarized. Nothing is silently dropped.
A session is what was said, in order, until you clear it.

Models may declare a context window — the prompt
then shows roughly how much of it is still free.

Nothing branches on the estimate. The server is the
authority on what fits, and it says so by saying no.

When it stops fitting, OneLoop says so and names the fix:
/clear, or a model with a larger window.

Summarizing a thread to keep it alive trades accuracy for length
on your behalf. /clear is the same move, made deliberately.

integration

Agent Status via OSC 7501

OneLoop emits the active model and turn state as OSC 7501
when running under Emacs comint.

ESC ] 7501 ; state=working|idle : app=oneloop : title=<base64 model> ESC \

state — working during a turn, idle between turns.

title — model alias (base64 UTF-8), so the client always knows
the current model even in idle.

A small oneloop.el filter reads these and updates the mode line:
model: computing... / model: idle.

Any terminal, editor, or tooling can consume it — no prompt scraping needed.

get started

Quick start

# 1. Start the local model (no key, nothing leaves the box)
./ols

# 2. Interactive REPL
./ol

# Reach a hosted model only if you want one
./ol login openrouter
./ol login opencode-go
./ol login openai  # ChatGPT Plus/Pro

# One-shot
./ol "explain this codebase"

# Pipe into it
git diff | ./ol "summarise these changes"
