OneLoop

One coding agent for your OpenRouter, OpenCode, and ChatGPT subscriptions —
plus Claude Code and Antigravity through their binaries, and a local model through llama.cpp.

core idea

One Agent Loop

Think → call tools → feed results back → repeat.
No plugins, no hooks, no middleware.

User prompt
→
Model thinks
→
Tool calls
→
Model thinks
→
Response

Loops until the model stops calling tools. All calls in a single turn run in parallel.

multi-model

One session, many models

Switch mid-conversation. Plan with the expensive model,
implement with the cheap one, ask a third for a second opinion.

(nvidia)> /model luna; plan how to split the parser
(luna)> /model nvidia; implement step 1 of that plan
(nvidia)> /ca is the plan still consistent with the code?
optional CLI subscriptions

Claude Code and Antigravity

When the corresponding CLI is installed, /help lists its slash commands. Claude Code uses /cc, /ca, and /cn; Antigravity uses /ag, /aga, and /agn.

These commands use your existing CLI subscription and keep your selected OneLoop model unchanged. The answer comes back as a reference message in this session, so the current model can reason about it. OpenAI subscriptions are supported separately through the Codex provider and ./ol login openai.

no request

Your own commands

Lead a line with ! to run bash yourself. The output is printed, then recorded in the session as reference material — no request is made, so nothing is spent until you ask for something.

(nvidia)> !cargo test 2>&1 | tail -20
(nvidia)> those two failures are mine — fix them
tools

Six tools

read File contents
write Create or overwrite
edit Search-and-replace
bash Shell commands
elisp Live Emacs state
skill Load a playbook

The skill tool joins the other five only when a skill file exists, so a repository with none runs with five.

skills

Skills

Markdown playbooks the model loads on demand.
Not in the system prompt — pulled in only when needed.

~/.oneloop/skills/code-review/SKILL.md
.oneloop/skills/changelog/SKILL.md
.oneloop/skills/migration/SKILL.md

Project skills come first, then global ones — a project skill shadows a global skill of the same name, and listing order is search order.

The model sees names + each skill's own frontmatter description.
It calls skill("name") when the task matches — no user action needed.

reliability

Append-only sessions

Every message, tool call, and result is appended to a JSONL file.
No mutation, no corruption.

.oneloop/sessions/2025-07-11.jsonl
.oneloop/sessions/2025-07-11-001.jsonl
reliability

No compaction

Nothing is summarized. Nothing is silently dropped.
A session is what was said, in order, until you clear it.

Models may declare a context window — the prompt
then shows roughly how much of it is still free.

Nothing branches on the estimate. The server is the
authority on what fits, and it says so by saying no.

When it stops fitting, OneLoop says so and names the fix:
/clear, or a model with a larger window.

reliability

Resilience

Retry with fallbackMakes up to 10 attempts by default on transient failures, then offers another model. The model you pick becomes active for the session once it answers, and config is never written; a rejected request fails at once
Bounded waitsConnections and finite responses time out; an active stream may run long, but a stalled one cannot
Parallel toolsMultiple calls execute concurrently
Output truncationLarge outputs trimmed before re-entering context
Stop anywhereCtrl+C stops cleanly; session preserved
AGENTS.mdLoaded as system prompt if present
Engineering tenetsFive built-in rules — correct, look it up, verify, one way, don't break — carried into every prompt, with or without an AGENTS.md
get started

Quick start

# Install the release: oneloop plus the ol alias, into ~/.local/bin
curl --fail --silent --show-error --location \
  https://raw.githubusercontent.com/oneness/OneLoop/main/install.sh | sh
# Interactive REPL
ol
# Hosted model, only if you want one
ol login openrouter
ol login opencode-go
ol login openai  # ChatGPT Plus/Pro
# One-shot, or piped
ol "explain this codebase"
git diff | ol "summarise these changes"
# From a checkout: ./ols runs the pinned local model, ./ol runs the tree
./ols
